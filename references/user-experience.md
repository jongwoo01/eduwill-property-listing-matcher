# 사용자 안내

문구가 필요할 때 해당 절만 읽는다. 내부 명령보다 현재 상태·안전 상태·다음 행동을 먼저 말한다.

## 매물장 준비 4단계

- `매물장 준비 1/4 · 저장 방식` — Google Sheets / 이 컴퓨터의 Excel
- `매물장 준비 2/4 · 자료 받기` — 파일·폴더·링크·채팅·빈 매물장
- `매물장 준비 3/4 · 자료 정리` — 처리 건수와 확인 필요 건수
- `매물장 준비 완료` — `[매물장 열기]` 또는 클릭 가능한 Excel 파일 경로

단계가 실제로 바뀔 때만 한 줄로 표시한다. 기존 사용자의 검색·수정에는 단계를 다시 붙이지 않는다.

## 검색 결과 안내

먼저 `조건에 맞는 매물 N건`, 다음으로 `확인 필요 N건`을 말한다. 상위 3건은 번호·핵심 조건·맞는 이유·확인할 값을
보여주고, 개인정보와 내부 JSON은 숨긴다. 끝에는 “이 중 손님에게 보낼 문안으로 정리해줘” 같은 다음 요청 하나를 둔다.
요청이 오면 `client-message.md`의 구조를 따른다. `warnings`가 있으면 결과 건수 다음에 한 줄로 알린다.

## 추가·수정·완료 확인

쓰기 전에는 매물 식별정보와 바뀌는 값만 보여준다. 완료 후에는 처리 건수, 보류/확인 필요 건수, 운영 원본 링크를 준다.
불완전한 입력은 “아는 값으로 저장했고, 확인 전까지 보류됩니다”라고 알린다.

## 오류와 복구

항상 세 가지를 함께 말한다.

1. 실패한 지점
2. 안전 상태 — 예: `원본 파일: 변경하지 않음`, `기존 매물장: 그대로 유지`
3. 사용자가 할 다음 행동 하나

Google 인증 실패는 재연결을 안내하고 Excel로 몰래 전환하지 않는다. Excel 파일 누락은 새 빈 파일을 만들지 말고 경로를
다시 받는다. 해시 충돌은 최신 파일을 다시 읽고 변경안을 새로 보여준다.

## 피해야 할 문구

- `처리할 수 없습니다`만 말하기
- 빈 값이 있다는 이유로 전체 입력 거부하기
- 사용자에게 CLI·스키마·셀 범위를 첫 문장으로 설명하기
- 로컬 Excel 선택자에게 Google 연결을 요구하기
- Google 선택자에게 임시 CSV를 최종 원본으로 제시하기

## 완료 전 UX 점검

- 사용자가 선택한 저장 방식과 실제 운영 원본이 같은가?
- 원본 보존 여부와 처리/보류 건수를 알렸는가?
- 링크 또는 클릭 가능한 절대 경로가 있는가?
- 다음 행동이 하나로 명확한가?
- 실패 시 안전 상태와 복구 행동이 있는가?

매물장 전환에서는 `기존 Google 시트와 연결`, `이전 매물장으로 돌아가줘`, `기존 이름 덮어쓰기 금지`도 이해해야 한다.
삭제 요청에는 행을 지우지 않고 `상태=완료` 또는 `보류`로 바꾼다고 안내한다.
