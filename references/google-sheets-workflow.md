# Google Sheets 운영 절차

도구 실행과 사용자 안내를 분리한다. 아래 기술 절차를 수행하되 사용자에게는 `user-experience.md`의 상태·완료·복구
문구를 사용하고, 기술 진단을 요청받지 않으면 API 이름·범위·오류 원문을 노출하지 않는다.

## 기본 원칙

- Google 시트를 운영 원본으로 사용한다.
- 새 시트 생성·가져오기·편집에서는 현재 런타임의 Google Sheets 작업 스킬을 먼저 읽고 따른다.
- 기존 시트는 사용자가 명시적으로 수정 또는 운영 원본 연결을 요청하기 전까지 읽기 전용으로 취급한다.
- 시트 제목이나 기본 탭 이름을 추측하지 않고 메타데이터에서 실제 이름과 `sheetId`를 확인한다.
- 새 매물장이나 매물장 전환은 연결(프로필) 변경이지 삭제가 아니다. 기존 Google 시트와 저장된 연결은 보존한다.
- 매 요청 시작 시 `get_spreadsheet_metadata`로 시트가 실제로 열리는지 확인한다. 이것이 연결 확인의 전부다.

## 새 시트 생성

1. `매물` 28열과 `매물상세` 20열로 이루어진 워크북 계획을 세운다. 헤더 정본은 `assets/매물장-템플릿.csv`와
   `assets/매물상세-템플릿.csv`이며, 한 글자도 바꾸지 않고 그대로 쓴다.
2. 사용 가능한 시스템 스프레드시트 기능으로 로컬 `.xlsx`를 만든다.
3. Drive 스프레드시트 가져오기 도구에 절대경로와 `upload_mode: native_google_sheets`를 전달한다.
4. 변환 응답에서 네이티브 Google 스프레드시트인지, 새 ID와 URL이 반환됐는지 확인한다.
5. 메타데이터와 헤더를 다시 읽어 제목, 두 탭, 행 수, 열 수를 검증한다.
6. 링크와 ID를 제공하고 Google 프로필을 저장한다.

기존 사용자가 새로 시작한 경우 새 파일은 별도의 Google 시트 ID로 생성한다. 기존 시트에 탭을 덮어쓰거나 내용을
비우지 않으며, 새 프로필을 활성화한 뒤에도 이전 프로필을 목록에 남긴다.

`.xlsx`를 일반 파일 업로드로 올려 Google 시트인 것처럼 보고하지 않는다. 성공한 경우 최종 결과에는 로컬 중간 파일이
아니라 Google 시트 링크를 제공한다.

## 라이브 검색

1. 메타데이터에서 `매물` 탭의 실제 이름, 그리드 크기, 헤더 행을 확인한다.
2. 28개 헤더가 일치하는지 확인한다. 비표준이면 검색 결과를 단정하기 전에 이관 경로를 제시한다.
3. 검색 범위는 실제 데이터 직사각형으로 제한한다. 한 번의 행 검색이 50,000셀을 넘으면 행 단위로 나눈다.
4. 빈 검색어나 탭 이름만으로 전체 시트를 검색하지 않는다.
5. 결정적 순위 계산이 필요하면 이번 요청에서 읽은 최신 행만 임시 표준 CSV로 만들고 로컬 `search`를 사용한다.
6. 결과 행의 번호·상태·핵심 조건을 필요하면 라이브 시트에서 다시 확인한다.

## 추가·수정·완료

1. 변경 직전 메타데이터와 대상 행을 다시 읽는다.
2. 번호 열로 정확한 행을 찾고, 중복 번호가 있으면 중단한다. 추가는 번호 열 전체를 읽어 새 번호가 없는지 먼저 확인한다.
3. `get_cells`에 해당하는 라이브 셀 읽기로 기존 값, 수식, 데이터 검증을 확인한다.
4. 사용자에게 프로필 이름, 시트 링크, 탭, 번호, 변경 전후를 보여준다.
5. 확인 후 관련 셀만 하나의 범위가 명확한 배치로 변경한다.
6. 변경 셀을 다시 읽어 요청값과 일치하는지 검증한다. 사용자가 확인을 생략하라고 해도 2와 6은 생략하지 않는다.

추가는 기존 데이터 끝의 새 행에 수행하되 번호 중복을 먼저 검사한다. 완료 처리는 행 삭제가 아니라 `상태=완료`와, 알 수
있는 경우에만 `계약일`·`실제계약금액(만원)`을 갱신한다. 수식·서식·드롭다운은 대상 작업과 무관하면 보존한다.

## 실패 처리

- 인증 실패: 연결 계정과 권한을 안내하고 재인증한다.
- 시트·탭 없음: 저장된 ID를 추측으로 대체하지 않고 Drive 검색 또는 사용자 링크로 다시 식별한다.
- 범위 오류: 메타데이터를 다시 읽고 더 작은 정확한 범위로 재시도한다.
- 연결 도구 일시 실패: 로컬 CSV를 새 운영 원본으로 선언하지 않는다.
- 일부 쓰기 실패: 라이브 셀을 다시 읽어 실제 반영 범위를 확인한 뒤 남은 변경만 제안한다.

모든 실패 응답에는 다음 세 가지를 포함한다.

1. 사용자가 이해할 수 있는 한 문장 원인
2. 원본 또는 기존 시트가 변경됐는지 여부
3. 사용자가 할 다음 행동 하나

부분 완료라면 만들어진 Google 시트 링크를 먼저 제공하고 중복 시트를 만들지 않은 채 이어갈 방법을 안내한다.
