# Google Sheets 운영

Google Sheets 모드에서만 Google Drive 플러그인이 필수다. 플러그인이 설치·활성화되고 Google 계정 로그인이 끝나 다음
도구를 호출할 수 있어야 한다.

- `get_profile`: 현재 연결 계정 확인
- `get_spreadsheet_metadata`: 스프레드시트 ID와 탭 확인
- `get_spreadsheet_range` 또는 `get_spreadsheet_cells`: 헤더·값·수식 재조회
- `import_spreadsheet`: 표준 `.xlsx`를 네이티브 Google Sheets로 가져오기
- `batch_update_spreadsheet`: 범위가 좁은 부분 쓰기

Excel 모드에서는 이 플러그인을 검사하거나 요구하지 않는다.

## 연결 게이트

기존 Google 프로필의 작업에서는 다음 순서를 바꾸지 않는다.

1. 위 도구가 모두 사용 가능한지 확인한다.
2. `get_profile`의 이메일과 저장된 프로필 `account`가 같은지 확인한다.
3. 저장된 `sheet_id`로 `get_spreadsheet_metadata`를 호출하고 응답 ID가 같은지 확인한다.
4. 저장된 `listing_sheet`·`detail_sheet`가 존재하는지 확인한다.
5. 두 탭의 첫 행을 읽어 `sheet-schema.md`의 28열·20열 헤더와 정확히 비교한다.

계정·ID·탭 이름을 추측으로 바꾸지 않는다. 연결 게이트가 끝나기 전에는 검색 결과나 쓰기 성공을 보고하지 않는다.

## 오류 분류와 재시도

| 분류 | 처리 |
| --- | --- |
| 플러그인·도구 없음 | 설치 또는 활성화를 안내하고 중단 |
| 로그인·인증 오류 | 해당 Google 계정 재연결을 안내하고 중단 |
| 권한 없음 | 저장된 계정에 편집 또는 조회 권한을 부여하도록 안내 |
| 파일·탭 없음 | 정확한 시트 링크를 다시 받거나 탭 이름을 복구하도록 안내 |
| 계정·스프레드시트 ID 불일치 | 프로필을 자동 수정하지 말고 사용자가 의도한 원본을 확인 |
| 429, 5xx, 타임아웃 | 같은 호출을 한 번만 재시도; 다시 실패하면 일시 장애로 중단 |

Google 실패를 새 Excel이나 로컬 CSV로 자동 전환하지 않는다. 오류 응답은 “어느 단계에서 실패했는지”, “기존 원본은
변경되지 않았는지”, “사용자가 할 다음 행동 하나”만 명확히 말한다. 일부 쓰기 오류면 대상 셀을 다시 읽어 실제 반영
범위를 먼저 확인한다.

## 새 Google 매물장

1. 플러그인, 현재 계정, 필요한 도구를 확인한다. 아직 저장된 ID가 없으므로 ID 일치 검사는 하지 않는다.
2. `profile list`로 사용할 고유 프로필 이름을 import 전에 정한다.
3. 현재 런타임의 스프레드시트 작성 지침으로 `매물` 28열·`매물상세` 20열의 로컬 `.xlsx`를 만든다.
4. 로컬 파일의 두 탭과 헤더를 검증한다.
5. `import_spreadsheet`에 절대경로와 `upload_mode: native_google_sheets`를 전달한다.
6. 반환된 새 ID·URL과 네이티브 Google Sheets 변환 성공을 확인한다.
7. 새 ID에 메타데이터·탭·헤더 검사를 적용하고, 현재 계정과 함께 프로필을 저장·활성화한다.

일반 Drive 파일 업로드를 Google 시트 성공으로 간주하지 않는다. 기존 시트나 프로필을 덮어쓰지 않으며 최종 응답에는
새 Google Sheets 링크를 준다.

가져오기는 성공했지만 이후 검증이나 프로필 저장이 실패하면 새 시트를 삭제하지 않는다. 이전 활성 프로필을 유지하고,
만들어진 시트 링크와 실패 단계를 알린 뒤 그 시트 검증부터 이어서 할 수 있게 안내한다.

## 검색과 변경

- 검색은 실제 데이터 직사각형만 읽는다. 50,000셀을 넘으면 행 범위를 나눈다.
- 결정적 검색은 이번 요청에서 읽은 최신 행만 표준 형태로 전달해 로컬 `search`로 계산할 수 있다.
- 변경 직전 대상 행과 번호 열을 다시 읽는다. 상세행은 `매물` 번호 열에 같은 번호가 있을 때만 수정·추가한다.
- 추가는 현재 `매물`의 28열 행을 읽고 로컬 `prepare-add --existing-json '<기존행 배열>' --record-json '<신규행 배열>'`로
  번호, 보류 상태, 중복 경고를 확정한다. 한 번에 최대 1,000건만 준비한다.
- 사용자 확인 뒤 관련 셀만 `batch_update_spreadsheet`로 변경한다.
- 같은 셀을 다시 읽어 값·수식·검증이 의도대로인지 확인한다.
- 완료는 행 삭제가 아니라 `상태=완료`다. 다른 수식·서식·드롭다운은 건드리지 않는다.

여러 건 추가는 준비된 연속 행을 좁은 한 배치로 쓴다. 오류나 타임아웃이 나면 배정한 번호의 범위를 다시 읽어 반영·미반영을
나눈다. 미반영 건은 같은 번호와 값으로만 재시도하며 새 번호를 발급하지 않는다. 계약 완료 요청에 계약일이나 실제계약금액이
포함되면 `매물.상태=완료`와 해당 `매물상세` 값을 하나의 변경안으로 확인받는다. 실제 금액을 호가로 추정하지 않으며, 두
범위를 함께 쓰지 못하면 각각 재조회해 부분 성공을 그대로 보고한다.
